# Project

Building a **standalone Go daemon** that performs **one-way sync from Readest → BookOrbit** without KOReader.

The bridge polls Readest Cloud for changed books and pushes reading progress to BookOrbit.

Language: **Go**

# Completed

## Investigation

A deep reverse-engineering pass was completed over both plugins.

## Important findings

The report confirmed:

* Readest is the only source of truth.
* BookOrbit is write-only.
* Hash parity already exists via partial MD5.
* Polling is the correct architecture.
* No KOReader runtime is needed.
* Bulk Progress endpoint should be preferred.
* Match-check should cache mappings.
* Watermark is:

```
max(
    synced_at,
    updated_at,
    deleted_at
)
```

* Token refresh follows the exact plugin behavior.
* Many subtle implementation corrections were discovered and documented.

# Important guidance

Do **not** merge milestones together.

Foundation should contain only:

* Go module
* package layout
* config
* logger
* utilities
* state abstraction
* shared models
* HTTP client interfaces/stubs
* CLI skeleton
* Makefile
* example config
* README
* test scaffolding

No business logic.

No auth.

No API calls.

No sync.

No polling.

No retries.

# Design philosophy

The project prioritizes correctness over speed:

* Reverse engineer first.
* Validate understanding.
* Build in small, reviewable milestones.
* Treat plugin behavior as canonical for runtime behavior.
* Treat planning documents as architectural guidance.
* If planning and plugin behavior conflict, stop and explain before implementing.
